# GenAI Adoption Pipeline

Firm-level measurement of **Generative-AI adoption in the Swiss labor market** from online
job-posting data, using keyword-based classification. See the top-level
[`README.md`](../README.md) for the current (v7) scoring methodology — the
Explanations docs below describe the pipeline's *original* design, parts of
which are now superseded (flagged where relevant).

The pipeline ingests job advertisements, identifies the postings that reference Generative-AI
tools and skills with a data-driven keyword classifier, and aggregates the results into
firm-, occupation-, industry-, and time-series-level adoption metrics.

## Quick start

```bash
pip install -r requirements.txt
python code/mine/run_full_pipeline_step1_3.py
```

This runs Phase I (data prep) → language mapping → keyword-group classification on
the full combined dataset, reading from `pipeline/config.yaml` (update `data_path`
first — see the top-level README's "Expected data layout"). The script `chdir`s
itself into `genai-adoption-pipeline/` and puts it on `sys.path`, so it can be run
from anywhere — no manual `PYTHONPATH` needed for this one. Both
`data_preparation.py` and `language_detection.py` reprocess everything from scratch
each run (no skip-logic); `group_classification.py` skips any file already
classified, so a killed/interrupted run resumes cheaply from the classification step.

Then, for the v7 scoring results and dashboards — these three do NOT self-locate
like the script above, so `cwd` and `PYTHONPATH` need to be set explicitly:

```bash
cd genai-adoption-pipeline
set PYTHONPATH=<full path to code\mine>;<full path to genai-adoption-pipeline>
python -u ..\code\mine\build_v7_dashboard.py
python -u ..\code\mine\build_results_dashboard_v4.py
python -u ..\code\mine\build_layer_breakdown_dashboard.py
```

(PowerShell: `$env:PYTHONPATH = "<...>;<...>"` instead of `set`.) Each reads fresh
from `output/classified_data` and is independent of the others — order doesn't
matter.

## Layout

- `pipeline/` — the four live modules (`config_loader.py`, `data_preparation.py`,
  `language_detection.py`, `group_classification.py`) and `config.yaml`. Keyword
  matching (`group_classification.py`) does word-boundary regex matching against a
  normalized version of each ad's text — see the module docstring for the
  normalization rules (accent-stripping, German digraph handling, plural/declension
  patterns per language).
- `keyword_lists/` — `master_keywords.json`, the active, finalized keyword list
  (117 keywords, EN/DE/FR/IT forms).
- `output/` — generated by running the pipeline; not included in this package (see below).
- `Explanations/` — documentation (start above).

## Output

Everything under `output/` is generated by running the pipeline — this package ships
none of it. Once you run it, expect:

| Path | What it is | Generated by |
|---|---|---|
| `output/prepared_data/year=YYYY/*.parquet` | Phase I output — cleaned, filtered, deduplicated job ads, plus detected language | `pipeline/data_preparation.py`, `pipeline/language_detection.py` |
| `output/classified_data/year=YYYY/*.parquet` | Same rows as `prepared_data`, plus `group` and `matched_group_keywords` | `pipeline/group_classification.py` (via `code/mine/run_classification_only.py` or the full pipeline) |
| `output/plots/v7_dashboard.html` | v7 methodology results: per-keyword G1/G2 classification, breakeven-`c` table, `c`/`k` grid-sweep charts | `code/mine/build_v7_dashboard.py` |
| `output/plots/results_dashboard_v4.html` | Keyword-classification methodology dashboard: matches per group, classification breakdown, GenAI-mention share over time, language distribution, raw keyword volumes, full 117-keyword table, elbow plots, false-positive-risk discussion | `code/mine/build_results_dashboard_v4.py` |
| `output/plots/layer_breakdown_dashboard.html` | Corroboration/QA view: keyword coverage by Group and by source layer (Stanford AI Index / Hosseini & Lichtinger / LLM-brainstormed) | `code/mine/build_layer_breakdown_dashboard.py` |

All three dashboards are self-contained single HTML files — open directly in a
browser, no server or Python install needed on the viewing machine.
