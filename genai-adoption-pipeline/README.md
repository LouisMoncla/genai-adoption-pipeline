# GenAI Adoption Pipeline

Firm-level measurement of **Generative-AI adoption in the Swiss labor market** from online
job-posting data, using econometrically validated (DHS structural-break) keyword detection.

The pipeline ingests job advertisements, identifies the postings that reference Generative-AI
tools and skills with a data-driven keyword classifier, and aggregates the results into
firm-, occupation-, industry-, and time-series-level adoption metrics.

## Quick start

```bash
pip install -r requirements.txt
# from the repo root (Internship/), with genai-adoption-pipeline/ on PYTHONPATH:
python code/mine/run_full_pipeline_step1_3.py
```

This runs Phase I (data prep) → language mapping → keyword-group classification on
the full combined dataset, reading from `pipeline/config.yaml` (paths in that config
are relative to `genai-adoption-pipeline/`, which the script `chdir`s into). Both
`data_preparation.py` and `language_detection.py` reprocess everything from scratch
each run (no skip-logic); `group_classification.py` skips any file already
classified, so a killed/interrupted run resumes cheaply from the classification step.

`pipeline/main.py` (now under `pipeline/legacy/`) was the *original* entry point —
superseded, not runnable as the "quick start" anymore. See
`pipeline/legacy/README.md` for why.

## Layout

- `pipeline/` — the four live modules (`config_loader.py`, `data_preparation.py`,
  `language_detection.py`, `group_classification.py`) and `config.yaml`
- `pipeline/legacy/` — the original Phase II design (regression-based group
  assignment, translation, aggregation), superseded — kept for provenance, not run
- `keyword_lists/` — `master_keywords.json`, the active validated keyword list
- `keyword_lists/legacy/` — the original raw candidate keyword lists it was built
  from, superseded — kept for provenance, not read by the active pipeline
- `output/` — generated artefacts (ships with the keyword-translation cache) — see below
- `Explanations/` — documentation (start above; two docs are marked LEGACY where
  they describe the superseded flow)

## Output

Everything under `output/` is regenerated by running the pipeline (`code/mine/` scripts
included) — none of it is committed to git except `keyword_translations.json`, which is
kept because it's expensive to regenerate (needs internet + translation API calls).

**Start with `output/plots/dashboard_v3.html`** (2026-08-02) — a single self-contained
file, double-click it and it opens in any browser, no server or Python install needed
on the viewing machine. 21 sections: everything from v2 (classification breakdown,
GenAI-mention share over time, matches per group, group share per year, proportion
table, occupation breakdown, top keywords, industry/firm-size/home-office/contract-
type/canton/firm-adoption breakdowns) plus new sections added for the 2026-08-02
rerun: keyword coverage by Group and source layer, a full Option A/B/C
combination-strategy comparison computed live (not just the elbow plot), a
comparison against Domenico's thesis benchmark, and a live-recomputed data-quality/
sanity-check summary (cross-year duplicate postings, etc.). Generated by
`code/mine/build_results_dashboard_v3.py` — the only dashboard-generating script
still present; v1/v2 were deleted once v3 superseded them (their history is
preserved in git, not on disk).

| Path | What it is | Generated by |
|---|---|---|
| `output/prepared_data/year=YYYY/*.parquet` | Phase I output — cleaned, filtered, deduplicated job ads, plus detected language | `pipeline/data_preparation.py`, `pipeline/language_detection.py` |
| `output/classified_data/year=YYYY/*.parquet` | Same rows as `prepared_data`, plus `ad_id`, `group` (`"1"`/`"2"`/`"3"`/`"NA"`), `matched_group_keywords` | `pipeline/group_classification.py` (run via `code/mine/run_classification_only.py`) |
| `output/plots/dashboard_v3.html` | **Open this first.** All headline charts + sanity-check summary in one file (see above) | `code/mine/build_results_dashboard_v3.py` |
| `output/plots/occupation_genai_share.png` | Static image of the occupation-share chart (also embedded in the dashboard) | `code/mine/occupation_genai_share_plot.py` |
| `output/plots/option_b_elbow.html` | Standalone interactive elbow plot for picking k (v3 embeds this chart directly instead of via iframe) | `code/mine/group_strategy_analysis.py` |
| `output/plots/group_strategy_analysis.csv` | Per-ad numbers behind the Option A/B/C combination-strategy comparison — raw data, not a plot, useful for spot-checking | `code/mine/group_strategy_analysis.py` |
| `output/keyword_match_counts_by_group_layer.csv` | Per-keyword ad-match counts (how many keywords, not ads, produced >=1 match), by Group and by source layer (St/H&L/LLM) | `code/mine/keyword_match_counts_by_group_layer.py` |
| `output/keyword_translations.json` | Cached per-language keyword translations (ships with the repo on purpose); only consumed by the now-legacy `pipeline/legacy/keyword_translation.py` path | `pipeline/legacy/keyword_translation.py` |
| `output/.cache/` | FastText language-ID model — no longer used for live language detection (x28's own `language` column is used instead as of 2026-08-02), kept only in case it's needed again | `pipeline/language_detection.py` |

To regenerate everything: `python code/mine/run_full_pipeline_step1_3.py` for
`prepared_data`/`classified_data`, then `python code/mine/build_results_dashboard_v3.py`
(from `genai-adoption-pipeline/`, with the repo root on `PYTHONPATH`) for the plots.
